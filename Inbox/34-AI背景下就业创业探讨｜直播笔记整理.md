# 34-AI背景下就业创业探讨｜直播笔记整理

这场课的主线是：[[Claude Code]]、[[Gemini]] 这类工具本身已经不再稀缺，真正能形成就业竞争力的是把 AI 用进真实工作流、企业落地、工程稳定性、安全审查、Agent / Skill 和具体行业场景里。

转写里有很多口语、玩笑、休息片段和明显错词；下面按主题整理，涉及灰产、简历虚构、证件、社保挂靠等不合规内容，只沉淀为风险提醒，不整理成可执行做法。

## 一句话总结

老师想表达的是：只会“买个 Claude / 会用 AI 写代码”已经不够了。接下来要卷的是能不能把 AI 变成企业工作流、AIOps Agent、知识库/RAG、自动化运营、硬件结合、传统企业提效和能写进简历的真实项目。求职上要尽快行动，创业上要低成本试错，但不要低估社会关系、合规、安全和长期投入的难度。

## 1. Claude / Gemini 普及后，工具本身不再是优势

开头老师判断：以前同学只要在面试里说自己注册了 Claude、能用 Claude Code，面试官可能会觉得很新鲜；现在朋友圈、公众号、技术圈都在讲这些工具，优势会迅速消失。

核心判断：

- 当一个工具“满大街都知道”时，它就不再是差异化能力。
- 只会付费使用 Claude、Gemini、Claude Code，不能形成竞争优势。
- 下一个阶段要卷的是企业级 [[AI工作流]]、[[Agent]]、[[Skill]]、本地模型、微调、传统企业落地、硬件结合。
- 下半年很多公司可能都会开始落地 AI 工作流，到时候再说“我会用 Claude”意义不大。

老师反复强调：AI 工具是增益，不是替代工程判断。真正的差距在“会不会提问、会不会拆任务、会不会学习、会不会把问题定位出来”。

## 2. 传统企业和非纯软件岗位反而有机会

老师提到，很多公司不一定让你去做传统软件开发，可能让你做：

- 硬件相关系统。
- 传统互联网企业或传统行业的 AI 提效。
- 企业内部运营自动化。
- 客服、内容、投放、数据看板等自动化工作流。
- 本地部署的大模型、微调、Agent 和知识库。

他举了上一期学员的就业情况：有不少人去了这类传统企业或三线城市岗位，工资可能听起来没有大厂高，大概两万多，但比较稳定，下班也早，老板重视 AI 提效。

这里的求职判断是：

- 不要只盯着纯前端、纯 React、纯全栈岗位。
- 传统企业对 AI 提效的需求很迫切。
- 稳定、离家近、工资够用的传统企业岗位，可能比听起来更适合很多人。
- 要能讲清楚怎么把 AI 工作流落到真实业务里。

## 3. 新型 AI 岗位：不一定写 React，但需要软件工程思维

老师展示了一个类似“公司首席大脑代理人”的岗位需求。它不是传统前端岗位，而是把创始人或 CEO 的战略想法转成算法、提示词库、自动化运营逻辑和工作流。

岗位内容大致包括：

- 基于 AI Agent 的全流程运营体系。
- 覆盖内容生成、社媒分发、多语言自动化客服。
- 把 CEO 的经营策略拆成高质量提示词库和自动化运营逻辑。
- 整合 GPT、Claude、Midjourney、Figma 等工具。
- 构建 24 小时运行的运营闭环。
- 建立 AI 监控看板，自动分析平台数据并优化投放/运营策略。

要求包括：

- 熟悉大语言模型底层原理。
- 精通 Agent Workflow / 代理工作流设计。
- 有 Python 或自动化工作流经验。
- 能听懂业务逻辑，不只是写代码。
- 思维方式是“如何用 AI 实现”，而不是第一反应招人。
- 有多语言和全球化运营意识。

老师强调：这类岗位看起来和 React 关系不大，但没有软件开发、系统拆解、流程设计、数据流和工程化思维，单纯买一个 Claude 也做不出来。

## 4. 3D / 图形学方向：机会少，但门槛高、护城河长

老师解释为什么图形学和 3D 没有继续重讲太多：国内前端 3D 岗位不多，主要集中在政府、国企、大型工程和外包场景。

典型方向：

- [[Three.js]]。
- WebGIS。
- 智慧城市。
- 电力系统可视化。
- 铁路、轨道、设备、场站等工业场景。
- 政府大屏和城市级 3D 可视化。

他的判断是：

- 做 3D 的岗位少，一灯出去 2000 多人里仍在做 3D 的不多。
- 但如果进去了，技能保质期很长，可能几年都围绕 Three.js / WebGIS 深耕。
- 3D 很吃知识，不像 Vue / React 那样可以快速拿来用。
- 能落地复杂 WebGIS、智慧城市、工业 3D 场景的人，公司不容易裁。
- 多数机会在外包或政府相关公司，真正进入甲方/国企直属单位很难。

所以 3D 不是大众路线，但如果有机会，需要有本事抓住。

## 5. AI + 医疗硬件：陀螺仪辅助下刀案例

老师用一个医疗器械项目说明 AI + 硬件的机会。

背景是手术下刀位置、角度、路径会影响出血量、孔洞大小、缝合难度和手术稳定性。高端医院有磁导航设备，可以识别病灶位置并辅助微创手术，但成本很高，并不是每个场景都能用。

他正在和医院主任、力学教授合作一个低成本方案：

- 把陀螺仪挂到手术针或相关器械上。
- 记录和校正下刀/进针轨迹。
- 用类似磁导航的数据作为参考，让学生或医生的操作逐步接近更优轨迹。
- 硬件成本不到 3000 元，加软件和人工成本也很低。
- 医疗器械设备和耗材有较强商业空间。

老师的延伸判断：

- AI 不只是写代码，也能加速硬件方案设计。
- 现在有工具可以根据想法推荐电路板、元件、接线方式和实现路径。
- 传统行业、硬件行业、医疗器械、电力行业里都有 AI 提效机会。
- 关键是能找到真实场景、真实专家和真实落地入口。

## 6. 创业现实：不要把“社会上飘”想得太浪漫

老师回顾自己从 2016 年开始不打工、做培训和社会项目的经历。他的核心感受是：创业和自由职业很难，远比上班更需要资源、人脉、关系处理、销售和抗压。

他说上班和在社会上接项目的差别很大：

- 上班时系统挂了，很多时候只是工作问题。
- 自己出来做事，客户问题、关系问题、收入问题都直接压到自己身上。
- 这个月搞不定，下个月可能就没有饭吃。
- 不是技术好就一定能赚到大钱，营销、资源和关系都很关键。

他举了培训行业早年广告投放、公众号买断、同行刷量、冒充分公司、学校合作关系等例子，说明商业竞争很累，也很脏。

结论是：

- 如果想创业，先判断自己有没有门道、人脉、资源和销售能力。
- 技术癖不能直接变成收入。
- 不要只看别人赚了多少，要看自己是否适合那套玩法。
- 能来学习、做项目、慢慢找工作，也是一条更稳的路。

## 7. 求职心态：尽快行动，不要陷在焦虑小作文里

老师提到收到很多同学的小作文，内容集中在抑郁、压抑、迷茫、懊悔、不知所措。他一方面理解，另一方面也提醒大家不要只情绪输出而不推进学习和项目。

他的课程重点已经从纯技术癖转向就业导向：

- 以前会完整讲很多小册子题目。
- 现在会挑对就业、面试、项目最有帮助的内容讲。
- 能坚持听枯燥内容的人，通常找工作也不会差。
- 但现在更重要的是做出项目、形成工作流、尽快进入投递。

## 8. 博彩 / 灰色岗位：有钱但会摧毁人，要谨慎

老师提到日本合法博彩相关岗位，认为它和菲律宾、柬埔寨那类扣护照风险不同，但仍然会对人的意志产生很强摧残。

他的态度是：

- 不到人生穷途末路，不建议轻易碰。
- 长期做博彩页面、后台、App，会改变人的价值感和心理状态。
- 有些岗位合法、有工签、工资高，但精神成本很大。
- 菲律宾、柬埔寨等扣护照场景风险极高。

这部分不作为职业建议，只作为风险提醒。

## 9. 简历和 Gap：不要让时间线变成硬伤

转写里老师对 gap 的表达很激进，但可以整理成更稳妥的求职原则：

- 两三个月以上的空档会被面试追问。
- 长 gap 如果解释不好，会显得不稳定。
- 不建议在 Web2 简历里虚构可被背调的公司经历。
- 更建议用课程项目、自由职业、开源项目、顾问项目、真实作品、学习产出，把时间线解释清楚。
- Web3 / AI 项目也要能说清业务、代码、架构和风险，不要只堆名词。

老师反复强调：面试官会追细节，写进去的东西必须能讲。

## 10. AI Coding 的工程稳定性案例：PM2 进程数打爆内存

老师讲了一个企业部署事故：客户现场系统运行一段时间后崩溃，技术团队排查不出来，客户被晾着，老板很生气。

系统结构大致是：

- 前端。
- Node 渲染层。
- Java 后端。
- Redis。
- SQL 集群。
- 多个 Docker。
- 一台 24GB 左右内存的机器。
- PM2 启动多个 Node 进程。

问题原因：

- PM2 启一个 Node 进程可能消耗约 1.2GB 到 2.7GB 内存，取决于程序。
- 机器只有 24GB。
- 他们按 12 核启动 12 个进程。
- 如果一个进程平均 2GB 以上，启动瞬间就接近或超过机器内存。
- 再叠加 Redis、Java、Docker、IO 请求，系统就崩。

解决方法：

- 不要盲目按核数开满 PM2。
- 根据用户量和机器内存，把进程数降到 4 个或 6 个。
- 前面用 Nginx 做代理即可。
- 给 Redis、Java、数据库和系统本身留下足够内存。

老师用 WARP 通过 SSH 查看机器状态、Docker 状态、后台日志，约 15 分钟定位问题。他强调这不是高深算法，而是懂工程现场、懂日志、懂资源和懂怎么问 AI。

## 11. AI 代码安全案例：14 个 P1 高危漏洞

另一个案例是跨境金融项目上线前交给安全团队扫描，发现 14 个 P1 高危漏洞。

典型问题：

- 前端收了验证码，但后端没有真正校验。
- 如果攻击者拿到 cookie，就可能绕过关键操作。
- 用户头像直接上传到 S3，图片 EXIF 里可能含地理位置、设备信息、拍摄信息。
- 如果 S3 地址公开或被嗅探，用户隐私会泄露。
- 还有注入类、接口校验类等漏洞。

修复方向：

- 后端必须校验验证码和关键权限，不能相信前端。
- 上传图片前要去除 EXIF 元数据，可以重编码、截图式重生成或专门清理元数据。
- 安全扫描和人工 review 都要落实到人。
- AI 写代码后必须有工程质量、安全质量和 review 机制。

老师总结了 AI 工程质量相关的面试题方向：

- 怎么保证团队使用 AI 的一致性。
- 怎么保证工程质量。
- 怎么保证代码安全。
- 怎么让 AI 写出来的系统部署到客户那里不挂。

## 12. 线上 / 本地架构：要懂概念，能画出体系

老师复盘了一套云上和本地架构，强调不要求每个细节都精通，但必须知道概念、能说清系统层次。

云上常见组件：

- CloudFront / CDN。
- WAF / 防火墙。
- ALB / NLB / 负载均衡。
- EC2。
- Lambda。
- AppSync。
- CloudWatch。
- S3。
- Aurora / RDS。
- ElastiCache / Redis。
- SQS。
- ECS。

本地或私有化环境常见组件：

- 硬件防火墙。
- Nginx。
- HAProxy。
- Keepalived。
- Node / Java / Go / Python 服务。
- Kafka / RabbitMQ / SQS 等消息队列。
- MySQL / PostgreSQL。
- Redis。
- MinIO 作为类 S3 对象存储。
- 本地日志采集和监控平台。

消息队列要能讲：

- 削峰填谷。
- 异步解耦。
- 重试机制。
- 死信队列。

缓存和数据要能讲：

- 多级缓存。
- 热点数据预热。
- 高可用。
- 持久化。
- 读写分离。
- 冷热数据分层。

老师给出的一个通用优化原则是：很多性能和稳定性优化，本质都是“把东西变小”。任务拆小、数据拆小、冷热分离、首屏资源变小，系统自然更稳定。

## 13. 冷热数据与读写分离

老师用金融系统举例：如果一年有很多转账记录，不一定都压在同一个写库上。

可以考虑：

- 当前高频读写走主写入实例。
- 历史数据、一年以上转账记录进入冷数据或读实例。
- 读写分离可以降低主库压力。
- 云数据库通常已经提供 reader / writer 集群能力。

面试里可以把它讲成“数据分层 + 读写分离 + 冷热数据归档”。

## 14. AIOps Agent：很适合写进简历

这场课一个很重要的落点是 [[AIOps Agent]]。

老师希望大家能在简历里写一个能落地的 Agent，尤其是用于工程稳定性的 Agent：

- 前端错误上报。
- 后端错误上报。
- 日志采集。
- 指标监控。
- 可视化告警。
- 通知渠道。
- 日常自动分析。
- 异常模式聚类。
- 根因定位。
- 性能瓶颈分析。
- 安全风险识别。
- 自动生成工单。

线上可选 Sentry / CloudWatch，本地可做日志采集和自建监控。关键是把这些数据喂给 AI Agent，让它自动分析、告警、归因和提出修复建议。

老师特别强调私有化部署场景：

- 有些客户不会给外部开放 IP。
- 国家级或重要项目可能完全不允许远程连。
- 没有本地 Agent，就只能派人去现场排查。
- 如果部署本地模型 + AIOps Agent，可以在客户内网辅助排查，减少现场成本。

这是很好的简历故事：不是“我会用 AI”，而是“我把 AI 接入了监控、日志、告警和故障排查链路”。

## 15. Agent 和 Skill 是刚需

老师提出：现在简历上最好要有两个东西：

- [[Agent]]
- [[Skill]]

Agent 可以是：

- AIOps Agent。
- 金融业务 Agent，例如用户直接说“给某某转 50 美元”，Agent 负责交互和执行流程。
- 企业知识库 Agent。
- 自动化运维 Agent。

Skill 不一定要奇思妙想，重点是有一个“绝活”。老师建议从历史上成熟的工作流里找灵感，把旧的可视化流程变成可复用的代码化 Skill。

## 16. N8N / Dify / Coze：工具不重要，工作流思路重要

老师回顾了 N8N、Dify、Coze 这类可视化工作流工具：

- 它们通过拖节点，把请求、JSON、字段处理、模型调用、发布等流程可视化。
- 对不会编程的人友好，但复杂到一定程度又会卡住。
- 会编程的人往往更适合把这些流程代码化、工程化。
- 现在再单纯学 N8N / Dify，可能已经不是最优路线。

真正有价值的是把历史上经典工作流变成 Skill 或产品。

他列出的可转化方向包括：

- 全自动内容工厂：抓热点、分析趋势、生成小红书 / 抖音 / 公众号内容、用 Midjourney / SD 生成配图、自动排版、自动发布。
- SDR 销售机器人：从 LinkedIn 抓潜在客户、GPT 分析画像、自动写冷邮件、自动跟进、自动约会议。
- AI 客服和工单系统。
- AI Coding Team：拆 PRD、生成架构、生成代码、自动 review。
- 24 小时 AI 工作室。
- 多 Agent 决策系统。
- 金融分析工作流。
- AI 招聘辅助：简历筛选、面试总结、候选人信息整理。
- 自动化运维工作流。
- 企业数字员工。
- Dify 知识库：文档上传、切片、知识库检索、问答。

老师的核心判断：工具不重要，思路、落地、测试和跑通才重要。谁有思路并能把它落地，谁就更有价值。

## 17. GitHub 开源 Skill：用作品换机会

老师建议，如果 Skill 一开始卖不动，可以先开源：

- 把工作流做成 GitHub 项目。
- 写清楚安装、使用、场景和案例。
- 在 GitHub、Twitter、小红书、公众号等平台持续运营。
- 有热度后，可能带来赞助、咨询、企业合作或工作机会。

他认为这比只在简历上写“熟悉 AI 工具”更有说服力。同行、公司和客户会因为作品找到你。

## 18. 企业知识库 / RAG：非常现实的咨询需求

老师展示了一个企业培训需求，大致痛点是：

- 项目团队工作繁杂。
- 需要文档结构处理。
- 需要项目实施配置沉淀。
- 需要团队经验沉淀。
- 以前搭过知识库，但维护频率低、效果一般。
- 希望借培训落地一套流程，让大家能高效复用过往经验。

老师认为这类需求可以有不同交付方式：

- 简单方案：直接上一套知识库工具，挂 Qwen / DeepSeek 等国产模型。
- 中等方案：把老板会议纪要、项目文档、团队经验统一导入知识库。
- 高级方案：做完整 RAG 系统，重点优化召回、切片、权限、更新和检索质量。

这类项目可以写进简历，也可以作为低成本咨询或副业方向。核心是“企业知识共享 + RAG + Agent”。

## 19. 求职安全：下载软件、交钱面试、可疑网页都要警惕

老师专门提醒求职安全。

高危信号：

- 面试方要求你下载陌生软件。
- 面试需要先交钱。
- 对方让你打开可疑网址，说是先了解他们产品。
- 对方很快索要大量个人信息。
- 英文沟通明显异常但包装得很像海外岗位。

安全建议：

- 任何陌生软件都不要下载。
- 面试交钱基本可以直接判定为骗局。
- 可疑网页不要在主力电脑打开，至少用虚拟机或隔离环境。
- 连接钱包、签名、Approve 时尤其小心。
- 有些网页可能诱导钱包授权，也可能挖矿导致电脑狂转。
- 英文不确定时，可以先让 ChatGPT 帮忙判断邮件或聊天是否异常。
- 不要在微信里聊敏感、违法或高风险信息。

## 20. 软件安全：不要装破解版和来路不明免费软件

老师提醒 Mac 也不是绝对安全，尤其是破解版软件：

- 破解软件常要求输入系统密码。
- 一旦授权，恶意插件或后门可能直接进入系统。
- 免费软件、破解软件、来路不明安装包往往成本最高。
- 几万块的电脑不值得为了几十块软件授权冒险。

建议是：能买正版就买正版，至少走可靠渠道，不要随便装破解包。

## 21. 社保、税务和身份连续性：要用合规方式处理

老师提到社保和税务的重要性，核心不是“挂靠技巧”，而是提醒大家不要让自己长期处于无社保、无收入证明、无纳税记录的状态。

现实影响：

- 医保能覆盖一部分看病成本。
- 大病医保有保障意义。
- 社保断缴会影响城市权益和身份连续性。
- 有合法收入、社保、税务记录，比长期无业状态更容易解释。

这里要注意：社保挂靠、虚假劳动关系等存在合规风险。更稳妥的原则是通过真实就业、灵活就业、合规个体经营或正规人事服务方式处理。

## 22. 工作渠道：Web2 + AI、Web3、传统企业和创业都要分清风险

老师提到现在大致有几类路：

- Web2 + AI：传统公司做 AI 提效、知识库、Agent、运营自动化。
- Web3 交易所：仍有岗位，但 headcount 不多，部分交易所裁员约 40% 后边裁边招。
- Web3 创业公司：不少项目有擦边或合规风险。
- 传统硬件/医疗/电力/政企：机会不一定多，但可能更稳定。
- 低成本创业或副业。

老师特别提醒 [[Prediction Market]] / 预测市场类项目风险：这类产品在国内语境下很容易被认定为赌博或开设赌场相关风险。找工作时不能只看钱，要判断业务本质和法律风险。

## 23. 低成本创业方向一：AI 短剧

老师认为 AI 短剧是当前最低成本创业方向之一，但不是无成本。

需要注意：

- 要有剧本、导演、剪辑、节奏和内容判断能力。
- 不投流很难起量，除非内容天赋特别强。
- 生成视频需要模型成本和加速成本。
- 最好用企业版工具，否则效率太低。
- 前期大概率要投入并亏钱。
- 一万以内试错，比开实体店便宜很多。

他举例有同学去 AIGC 公司做短视频，工资不高，但能学习完整短剧流程，包括导演、摄影、剪辑、剧本、投流和复盘。

## 24. 低成本创业方向二：小游戏 + 广告

另一个方向是小游戏：

- 微信小游戏。
- 抖音小游戏。
- 快手小游戏。
- 其他平台小游戏。
- 接广告变现。

老师认为这类方向有机会赚到钱，但要持续做、持续测试，不要指望一个小游戏立刻爆。

## 25. 低成本创业方向三：卖 Skill / 工作流 / AIGC 接单

老师更推荐程序员围绕自己的技能做轻资产尝试：

- 做 Skill。
- 做自动化工作流。
- 做 GitHub 开源项目。
- 做 Coze / Dify / Agent 工作流。
- 接 AIGC 短视频、海报、运营自动化等单子。
- 做企业知识库、RAG、培训和咨询。

他不太建议大家做模型中转站：虽然有人能月入几万，但太耗心思、太消耗精力。

## 26. Web3 撸毛：短期主义，不如做长期资产

老师提到 Web3 撸毛过去有人赚了很多，但现在熊市长，风险和时间成本都很高。

风险包括：

- 反撸。
- Gas 成本。
- 时间成本。
- 拿到的 token 跌得很厉害。
- 山寨币价值可能还不如成本。
- 项目周期太长，短期主义也变得不短。

他的建议是：尽量做有长期积累的事情，比如作品、Skill、知识库、项目、真实业务能力。

## 27. 实在找不到工作怎么办

老师最后给了比较现实的兜底判断：

- 第一目标仍然是找工作。
- 如果 Web2 / Web3 / AI 岗都找不到，可以尝试低成本创业或接单。
- 不要轻易送外卖，因为新骑手可能拿不到好单。
- 如果一定要做出行类工作，优先考虑客单价更高、客户更好的方向。
- 核心是生活还要继续，不要被焦虑压垮。

## 28. 可以立刻写进简历的项目方向

这场课里最适合沉淀成简历项目的方向：

- AIOps Agent：日志、指标、告警、异常归因、自动工单。
- 企业知识库 / RAG：项目经验沉淀、会议纪要、文档切片和召回。
- 自动化内容工厂 Skill：热点抓取、内容生成、配图、排版、发布。
- SDR 销售自动化：客户抓取、画像、邮件、跟进、预约。
- AI Coding Team：PRD 拆解、架构生成、代码生成、自动 review。
- 本地私有化部署 Agent：面向不开放公网 IP 的客户。
- 医疗 / 硬件 AI：传感器、数据采集、AI 分析、辅助决策。
- 传统企业 AI 提效：运营、客服、投放、数据看板。
- 小游戏 + 广告变现。

## 29. 行动清单

- 不要把“会用 Claude”当成核心卖点，要做出 Agent / Skill / 工作流。
- 至少准备一个能讲清业务闭环的 AI 项目。
- 把工程稳定性、安全漏洞、监控告警写成项目经验。
- 学会云上和本地架构的基本概念：负载均衡、缓存、队列、日志、对象存储、冷热数据。
- 尽快进入投递，不要一直等到“完全准备好”。
- 求职时警惕下载软件、交钱面试、可疑网页、钱包授权。
- 不装破解版软件。
- 长期看，选择有积累的方向：Skill、开源、企业知识库、AIOps、行业 AI。
